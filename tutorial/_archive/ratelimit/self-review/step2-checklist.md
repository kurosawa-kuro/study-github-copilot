# Step 2 自己採点シート

## Phase 分割の合格ライン

- [ ] Phase が 3 つ程度に分かれている（多すぎ・少なすぎは差し戻し）
- [ ] 各 Phase の想定行数が 300 行以内
- [ ] 各 Phase が単独で動作・テスト可能（積み上げ式）

## 各 Phase に含まれているか

- [ ] 目的（1〜2 行）
- [ ] 前提（直前 Phase の成果物）
- [ ] 変更/新規ファイル一覧（表）
- [ ] 公開インタフェース（シグネチャのみ、本体実装は書かない）
- [ ] 完了条件 **3 種全部**:
  - 機能条件
  - テスト条件
  - 検証コマンド（コピペ実行可能）
- [ ] ロールバック手順（1 行）

3 種揃わない Phase があれば Step 2 をやり直し。

## 推奨される分割

| Phase | 目的 | 行数目安 |
|---|---|---|
| 1 | Redis 接続抽象化 (`RedisKV`) | ~150 |
| 2 | レートリミット middleware 実装 | ~230 |
| 3 | 設定外出し + `X-RateLimit-*` ヘッダ | ~80 |

## 典型 NG 分割

- [ ] Phase 1 = 全部やる（300 行超過、テスト戻り判定が効かない）
- [ ] Phase 1 = middleware だけ、抽象化なし（密結合のまま積み上がる）
- [ ] Phase 2 で IaC も変更（Step 0-C で除外したはず）
- [ ] 完了条件に検証コマンドが無い

## 全体まとめに含まれているか

- [ ] 推奨実行順と理由
- [ ] Phase 間の依存関係
- [ ] リスクと対策
- [ ] 中止判断条件（最低 1 個）
