お疲れ様です、ご質問ありがとうございます。
社内で確認しました。以下にまとめます。

> Q1: 何 req / 何秒で制限すればよいでしょうか？

60 req / 60秒（固定窓）でお願いします。スライディングウィンドウまでは不要です。

> Q2: 対象 API はどこまでですか？

`/users` と `/orders` だけで大丈夫です。`/health` は監視で叩いているので除外してください。

> Q3: 超過時の HTTP ステータスとボディは？

429 でお願いします。ボディは `{"detail": "rate limit exceeded"}` で問題ないです。

> Q4: `Retry-After` / `X-RateLimit-*` ヘッダは付けますか？

`Retry-After` は必須でお願いします。`X-RateLimit-Limit` / `Remaining` / `Reset` も
成功時に付けてもらえると、フロントエンドで残量表示できるので助かります。

> Q5: 識別キーはユーザー単位ですか、IP 単位ですか？

認証済みは user_id で、認証なしは X-Forwarded-For 先頭 IP でお願いします。
ゲートウェイで X-Forwarded-For は正規化されています。

> ストレージ・環境について

Memorystore は既存を流用してください。dev / stg / prod すべて対象です。
監視・アラートは別チケットで切るので、今回のスコープ外で OK です。
