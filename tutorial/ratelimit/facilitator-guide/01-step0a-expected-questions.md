# 01. Step 0-A で受講者が出すべき問い

依頼書 `client-brief/2026-05-14_ratelimit.md` は意図的に薄い。
以下の `[QUESTION]` / `[AMBIGUITY]` が出ないと Step 0-A は未完了とみなす。

## 必須で出てほしい `[QUESTION]`

| # | 観点 | 期待される問い | ファシリの想定回答 |
|---|---|---|---|
| Q1 | 上限値・窓幅 | 「何 req / 何秒 で制限するか」 | **60 req / 60s（固定窓）** |
| Q2 | 対象 API | 「全エンドポイントか、一部か」 | `/users` と `/orders` のみ。`/health` は除外 |
| Q3 | 超過時応答 | 「HTTP ステータスとボディは」 | 429、ボディは `{"detail": "rate limit exceeded"}` |
| Q4 | レスポンスヘッダ | 「`Retry-After` / `X-RateLimit-*` は付けるか」 | **`Retry-After` 必須**、`X-RateLimit-Limit/Remaining/Reset` を成功時にも付与 |
| Q5 | 識別キー | 「ユーザー単位か IP 単位か」 | **認証済は user_id、未認証は X-Forwarded-For 先頭 IP** |

## 必須で出てほしい `[AMBIGUITY]`

| # | 箇所 | 分岐 |
|---|---|---|
| A1 | 「特定の顧客から大量リクエスト」 | 顧客単位（user_id / API key） vs IP単位 → Q5 で確定 |
| A2 | 「FastAPI のミドルウェアで」 | 全ルートに掛ける / 一部だけ → Q2 で確定 |

## あれば加点の `[QUESTION]`

- ストレージ: 既存 Memorystore を流用するか別インスタンスか → 流用
- 環境: 本番のみか dev/stg も含むか → 全環境
- 監視: メトリクス・アラートを Phase に含むか → **Non-Goal（別チケット）**
- IPv6 / プロキシチェーンの取り扱い → ゲートウェイが正規化済みの前提で受ける

## NG パターン（即指摘）

- 「一般的には 100 req/min なので 100 req/min とします」← **`[ASSUMPTION]` 無しで決めている**
- 対象 API を確認せず「全 API に適用」と書く ← `[AMBIGUITY]` を埋めずに決定
- 「FastAPI ミドルウェアで」と書いてあるのに `slowapi` 等の外部 lib 採用を勝手提案 ← 依頼書逸脱

## ファシリの動き

- 受講者の Step 0-A 出力を見て、上記 Q1〜Q5 が **すべて挙がっているか** チェック
- 抜けていた場合: 「依頼書に書かれていない決定が含まれていませんか？」と質問返し
- 全部出たら上の「想定回答」をまとめて返す（一度に出すと Step 0-A が一周で済む）
