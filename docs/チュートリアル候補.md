## 小規模（数時間 / `0-C → 1 → 3 → 4`）

### Redis 系

1. **Redis キャッシュをエンドポイントに追加**
    - 依頼例: 既存 FastAPI の `/users/{id}` に Redis キャッシュ（TTL 60秒）を追加
    - 学習: Redis キー命名規約、TTL 設計、fakeredis でのテスト
    - 想定: 1〜2時間

2. **分散ロック実装（SETNX + TTL）**
    - 依頼例: バッチ二重起動を防ぐため、開始時に Redis で分散ロックを取得（TTL 5分、リエントラント不要）
    - 学習: `SET NX EX` パターン、TTL によるデッドロック回避、レース条件の単体テスト
    - 想定: 1〜2時間

3. **ランキング機能（Sorted Set）**
    - 依頼例: ユーザースコアを Sorted Set で管理、TOP10 取得 API を追加、同点はユーザー ID 昇順
    - 学習: `ZADD` / `ZRANGE` / `ZINCRBY`、リアルタイム更新、fakeredis でのテスト
    - 想定: 2時間

4. **キャッシュ無効化パターンの導入**
    - 依頼例: 既存 User キャッシュに対し、PUT/PATCH 時の自動無効化（write-through）を実装
    - 学習: write-through / write-around の選択、影響範囲調査、`[BREAKING]` 判定
    - 想定: 1〜2時間

### Python バッチ系

5. **CSV → BigQuery 取込スクリプト**
    - 依頼例: GCS にアップロードされた CSV を読み、スキーマ検証後に BigQuery へ load。失敗時は別バケットに退避
    - 学習: `google-cloud-bigquery` クライアント、スキーマ検証、`[QUESTION]` で受入スキーマ確認
    - 想定: 2時間

6. **日次集計バッチ（Cloud Run Jobs 想定）**
    - 依頼例: BigQuery から前日分を集計し結果テーブルに書き込み、`--dry-run` オプション付き
    - 学習: 冪等性（同日2回実行しても結果不変）、dry-run の責務、Cloud Run Jobs エントリポイント
    - 想定: 2時間

7. **リトライ付き外部 API 呼出バッチ**
    - 依頼例: 外部 API を 1000 件分呼び、tenacity で指数バックオフ、結果を JSON で永続化
    - 学習: 例外設計、`[ASSUMPTION]` での失敗時方針表明、`responses` / `respx` でのモック
    - 想定: 1〜2時間

### Terraform 単体

8. **Cloud Storage バケット + ライフサイクルルール**
    - 依頼例: ログ保管用 GCS バケットを作成、30日後 Coldline、365日で削除、版管理オフ
    - 学習: `google_storage_bucket` のライフサイクルブロック、`terraform plan` 精読、`[QUESTION]` での保持要件確認
    - 想定: 1時間

9. **Cloud Scheduler ジョブの追加**
    - 依頼例: 既存 Cloud Run Jobs を毎日 03:00 JST に起動する Cloud Scheduler を Terraform で追加
    - 学習: cron 表記、OIDC 認証付き HTTP target、retry config の妥当値
    - 想定: 1時間

10. **IAM ロール最小権限化（既存リソースの改修）**
    - 依頼例: Service Account に付与済みの `roles/editor` を、実際に使う API に絞った最小権限ロール群に置換
    - 学習: 必要 API の洗い出し、`[ASSUMPTION]` での権限推定、`[BREAKING]` リスク、段階適用
    - 想定: 2時間

### GCP / セキュリティ

11. **Secret Manager 連携**
    - 依頼例: ハードコードされた API キーを Secret Manager 経由に切替
    - 学習: セキュリティ規約、Pydantic Settings、ADC 認証
    - 想定: 1時間

12. **ログ構造化（Cloud Logging 対応）**
    - 依頼例: print/logger を JSON 構造化ログに変換、trace_id を伝搬
    - 学習: タグ運用（`[BREAKING]`）、影響範囲調査
    - 想定: 2時間

## 標準（数日〜1週間 / `0-A → 0-C → 1 → 2 → [3→4]×N → 5-A`）

13. **レートリミット機能（典型例・最推奨）**
    - 依頼例: FastAPI middleware + Redis (INCR/EXPIRE) で API レートリミット実装
    - Phase 分割例: (1) Redis 接続抽象化 → (2) middleware 実装 → (3) 設定外出し
    - 学習: Phase 分割、Phase 間引き継ぎ JSON、Step 4 の戻り先判定
    - 想定: 1〜2日

14. **非同期ジョブキュー**
    - 依頼例: Redis Streams ベースのジョブキュー、producer / consumer 分離
    - Phase 分割例: (1) Stream 抽象化 → (2) producer → (3) consumer → (4) 統合
    - 学習: 設計判断、E2E テスト、累積副作用検査
    - 想定: 2〜3日

15. **意図的に曖昧な依頼: 「サイトを速くしたい」**
    - 依頼例: そのまま
    - 学習: Step 0-A の威力、`[AMBIGUITY]` / `[QUESTION]` の使い方を体感
    - 想定: 0.5日（要件明確化重点）

## 大規模（本番投入あり / `0-A → 0-B → 0-C → 1 → 2 → [3→4]×N → 5-A → 5-B`）

16. **新規マイクロサービス（API + キャッシュ + IaC）— 全工程通し**
    - 依頼例: FastAPI + Memorystore for Redis + Cloud Run を Terraform で構築・デプロイ
    - Phase 分割例: (1) Terraform リソース → (2) FastAPI アプリ → (3) Redis 統合 → (4) CI/CD → (5) 監視・アラート
    - 学習: アーキテクチャ判断（0-B）、terraform plan レビュー、ロールバック手順
    - 想定: 1週間

17. **既存サービスの Cloud Run 移行**
    - 依頼例: 既存ローカルサービスを Cloud Run + Memorystore 構成に移行
    - 学習: 互換性検証、E2E テスト、段階リリース戦略
    - 想定: 3〜5日

## インフラ専業（`0-C → 1 → 2 → [3→4]×N → 5-B`）

18. **Terraform module 化**
    - 依頼例: 散在しているリソースを module に切り出し、複数環境で再利用可能化
    - 学習: terraform plan の精読、state 移行、後方互換性
    - 想定: 1〜2日

19. **Memorystore + VPC のプロビジョニング**
    - 依頼例: Memorystore for Redis + VPC + Private Service Access + IAM + 監視 一式
    - 学習: GCP リソース連携、ネットワーク設計、コスト想定
    - 想定: 1〜2日

## 保守・改修（`0-C → 1 → 2 → [3→4]×N → 5-A`）

20. **N+1 問題の解消（Redis キャッシュ導入）**
    - 依頼例: ボトルネックエンドポイントの N+1 を解消、Redis でキャッシュ
    - 学習: 影響範囲調査、ベンチマーク、**戻り先判定（Step 1 戻りパターンを意図的に発生させる）**
    - 想定: 1〜2日

21. **ライブラリメジャーアップ（Pydantic v1 → v2）**
    - 依頼例: Pydantic v1 → v2 への移行、関連ライブラリも追従
    - 学習: `[BREAKING]` の運用、Phase 分割粒度、E2E 回帰テスト
    - 想定: 2〜3日

## 学習目的別の推奨順

| 学びたいこと | おすすめ順 |
|---|---|
| タグ運用（`[ASSUMPTION]` / `[BREAKING]`） | 1 → 12 → 7 → 10 |
| Phase 分割を体感 | 13 → 14 → 16 |
| 戻り先判定を試す | 20（意図的に Step 1 戻りを起こす） |
| Step 0-A 要件明確化 | 15 → 11 → 13 |
| Redis を一通り（キャッシュ以外も含む） | 1 → 2 → 3 → 4 → 19 |
| Python バッチ設計（冪等性・dry-run・リトライ） | 6 → 7 → 5 |
| `terraform plan` 精読 | 8 → 9 → 10 → 18 |
| IaC フローを通す | 8 → 9 → 19 → 16 |
| 全工程の通し稽古 | **16 が最強**（0-A から 5-B まで全 Step を使う） |
